    (CONSTRUCTION_SCOPES, FACILITY_SCOPES, PROPERTY_SCOPES). If you add a

    the correct default and a test asserts it.

  * A complete .po catalogue is not a translated screen. Odoo's extractor only
    sees a literal inside a _t() call, and the web catalogue is global across
    modules, so one module's translation masks another's gap. Measure Arabic
    by loading the screen and counting Latin words, not by counting entries.


HOW TO VERIFY ANYTHING YOU CHANGE

A green suite proves nothing about the UI, and admin proves nothing about
anyone else — the superuser is exempt from record rules. Every real defect
found on this branch survived because it had only ever been opened as admin.

  * Drive the running app (scripts/run-local.sh, Playwright with
    executable_path=/opt/pw-browsers/chromium). Wait on .o_main_navbar; never
    wait for networkidle — the bus long-polls and it never fires. RPC faults
    surface as .o_error_dialog, not as pageerror.
  * Use personas holding exactly one role each, plus a control account holding
    none. A screen that opens for the control is a leak; a screen that refuses
    a role that needs it is a broken feature. Both are silent.
  * Resolve action ids from ir_model_data at run time. Do not hardcode action
    IDs — they differ by database, and a wrong id reads exactly like a
    permissions failure.
  * Make every probe assert its own premise. A broken probe and a broken
    product look identical from outside.

Traps that have already cost time (details in START_HERE.md): _t() returns a
String subclass, so typeof reports "object" and a config walker will render
[object Object]; exists() bypasses record rules — use search(); Odoo's cache
lives on the transaction, so call env.invalidate_all() before reading as
another user; post_init_hook fires on install only — use
migrations/<version>/post-migrate.py for an installed module; hand-written RTL
blocks must sit inside /*!rtl:begin:ignore*/ … /*!rtl:end:ignore*/ (bang form);
Postgres in the container prints a misleading start failure and then comes up,
so poll pg_isready.
